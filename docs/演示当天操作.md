## 二、启动服务（两种模式，选一个）

### ⚠️ 先做这个判断：本机语音到底行不行

```powershell
python experiments/check_env.py
```

看「语音合成实测」这一行：

| 显示 | 含义 | 演示该怎么选 |
|---|---|---|
| ✅ 在线合成成功（音色好） | edge-tts 正常 | 用模式 A |
| ⚠️ 在线失败、已用离线兜底 | edge 挂了但 **SAPI 能出声**（音色差） | 用模式 A，声音 100% 有 |
| ❌ 合成失败：在线和离线都没成功 | **两句里平均有一句没声音** | **必须用模式 B** |

> 参考数据：在受限环境实测 9 句只有 6 句有声音（67%）。**如果自检是 ❌，就别赌模式 A。**

### 模式 A：真实模型（能应对临时提问）

```powershell
双击 run.cmd
# 或：
$env:DEEPSEEK_TEMPERATURE="0.3"
python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

| 项 | 实测表现 |
|---|---|
| 回复 | 真实大模型生成，能应对评委临时提问 |
| 延迟 | **平均 3.7 秒/句**（最快 2.9s，最慢 4.3s，9 句共 33.7 秒） |
| 声音 | 取决于上面那个自检；edge 抖动时靠 SAPI 兜底 |
| 断网 | 自动降到预置缓存，回复和声音都对（前提：照脚本念） |

### 模式 B：完全离线（保险，只认脚本 9 句）

```powershell
$env:DEMO_FALLBACK="1"
python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

| 项 | 实测表现 |
|---|---|
| 回复 | 预置的真实回复（彩排时录下的，质量已验证） |
| 延迟 | **约 3 毫秒/句**，9 句合计 0.02 秒（比模式 A 快 479 倍） |
| 声音 | **100%**（音频预生成，不碰网络） |
| 代价 | **只认脚本里那 9 句**，临时改词会掉成固定模板 |

> 启动后看 `/api/health`：`offline_mode` 为 `true` 就是模式 B，`false` 是模式 A。

## 三、什么时候切模式 B

| 现象 | 动作 |
|---|---|
| 发言人说到第二句还迟迟没反应 | 切模式 B（延迟从 5 秒变 0） |
| 连续两句没声音 | 切模式 B（声音 100%） |
| 现场网络明显不稳（投屏加载慢） | 直接切模式 B |
| 评委要临时提问 | **留在模式 A**（模式 B 答不出来） |

**切换方法**：关掉服务窗口，用另一条命令重启（10 秒）。所以**两个命令提前写在记事本里**，别现场敲。

## 四、演示时的三条铁律

1. **照 `docs/演示脚本.txt` 念**，别自由发挥——缓存只认这 9 句
2. **同一场景的 3 句连着说**——第 2、3 句是专门验证多轮记忆的，拆开就不成立了
3. **每句话说完等 5 秒再开口**——给语音合成留时间，抢话会显得很乱

## 五、出问题时的降级顺序

按这个顺序砍，**先砍影响最小的**：

| 顺序 | 砍什么 | 怎么砍 | 还剩下什么 |
|---|---|---|---|
| 1 | 语音输出 | 页面会只显示文字 + 表情变化 | 情绪 + 人设 + 记忆（核心价值都在） |
| 2 | 语音输入（改成打字） | 直接打字发送 | 同样的演示效果 |
| 3 | 实时模型 | 切模式 B | 预置回复（质量已验证） |
| 4 | 全部交互 | **放录屏** | 完整的演示效果 |

**录屏必须提前准备好**，这是最后一道保险。

## 六、当场一定会被问的三个问题（备好答案）

| 问题 | 怎么答 |
|---|---|
| **"你怎么训练的？"** | 我们没训练模型。用的是 DeepSeek 大模型 + 一份 400 字的人设提示词，加多轮记忆和情绪映射。三天项目做训练不现实。 |
| **"她能看见我吗？"** | **不能。** 摄像头只做本地预览，画面上传、也不送模型——这是刻意的隐私选择（ADR-008）。她感知的是你**说的话和语气**。 |
| **"断网了还能用吗？"** | 能。我们做了四级兜底：真实模型 → 预置问答缓存 → 多变体模板 → 纯文字。现场可以演示断网。 |
