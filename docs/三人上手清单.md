# 三人上手清单（每台新电脑照着做一遍）

预计 30 分钟。做完你就能和另外两人用同一套协作流程干活。

---

## 第 1 步：装工具

> ⚠️ 这些命令请在**你自己的 PowerShell 窗口**里执行，不要让我（AI）代跑 ——
> 装系统软件需要管理员权限和 UAC 弹窗，跑在沙箱里会失败。

```powershell
# 1) Git（本机还没装）
winget install --id Git.Git -e --source winget
# 装完关掉终端重开，验证
git --version
```

`winget` 不可用（提示找不到命令 / 无输出版本）时，用这两种退路之一：

- **手动下载安装包**：https://git-scm.com/download/win → 一路默认下一步
- **便携版免安装**：下载 PortableGit，解压到 `D:\tools\PortableGit`，
  再把 `D:\tools\PortableGit\bin` 加进系统 PATH（设置 → 系统 → 系统信息 → 高级系统设置 → 环境变量）

装好后**必须重开终端**，`git --version` 有输出才算成功。

# 2) Node.js（已装可跳过，需 >= 20）
node -v

# 3) Python 3.10（已装可跳过）
python --version
```

## 第 2 步：装 DSH

```powershell
npm i -g @deepseek-ai/dsh
dsh -V
```

## 第 3 步：配自己的 API Key

- 打开 DSH Web UI → **设置 → 模型**，填入**你自己的** DeepSeek API Key
- Key 只保存在本机 `D:\dsh_data\.dsh\.credentials.yaml`，**不会进仓库**，也不要发给队友
- 顺带在设置里把默认模型调成和队友一致（团队统一：`deepseek-v4-flash-vision-exp`，reasoning effort = high）

## 第 4 步：克隆仓库

```powershell
cd D:\
git clone <队长给的仓库地址> 情感交互智能体Agent开发
cd 情感交互智能体Agent开发
```

> 目录名建议就保持 `情感交互智能体Agent开发`，三人路径一致，文档里的路径才通用。

## 第 5 步：在 DSH 里打开这个目录

把 DSH 的工作区（workspace）设为
`D:\情感交互智能体Agent开发` 或你实际克隆到的路径，
然后开一个新会话。**验证成功**：AI 已经知道你们的分工和任务板 —— 它会自动读 `AGENTS.md`。

## 第 6 步：每日开工 / 收工

```powershell
# 开工：拉取队友的进展
.\scripts\sync.ps1 -PullOnly

# 收工：提交并推送
.\scripts\sync.ps1 -Message "feat: 感知层完成情绪分类接口"
```

如果脚本被系统拦住（提示「禁止运行脚本」，执行策略问题），用这条绕过：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\sync.ps1 -Message "feat: xxx"
```

> 脚本名是英文的（`sync.ps1` / `init-repo.ps1`），敲命令不用切输入法。
> 脚本内部会自动找 `git.exe`，所以**即使 PATH 坏了也能跑**。

## 每天的实际节奏

| 时段 | 做什么 |
|---|---|
| 开工 | `git pull` → 打开 `docs/团队任务板.md` 看「进行中」和「交接记录」 |
| 干活 | 在任务板上把自己任务改成「进行中」；只碰自己模块 |
| 中途 | 每完成一个小块就 commit + push，别攒 |
| 收工 | 更新任务板状态 + 写「下一步」→ push |
| 卡住 | 在任务板「卡点」栏写清楚，别自己闷一天 |

## 三条最容易踩的坑

1. **忘了 pull 就开始改** → 冲突全砸在自己头上。开工第一件事永远先 pull。
2. **把数据集/模型塞进仓库** → 队友每次 pull 都要等半天。大文件一律走云盘 + 登记 `data/MANIFEST.md`。
3. **三个人的 AI 各说各的** → 因为没更新任务板。任务板不真实，等于没有协作。

## 出问题时

| 现象 | 处理 |
|---|---|
| `git` 找不到 | 装完 Git 必须**重开终端**。若还是不行，多半是 PATH 指错了（见文末《PATH 修复》） |
| `dsh` 找不到 | `npm i -g @deepseek-ai/dsh` 后重开终端；或 `npm ls -g --depth=0` 看是否装上 |
| PowerShell 禁止运行脚本 | 见上面 `-ExecutionPolicy Bypass` 那一行 |
| clone 私有仓库要认证 | 用 Gitee/GitHub 的「个人访问令牌」当密码，别用账号密码 |
| AI 好像不知道项目背景 | 确认你是在 `情感交互智能体Agent开发` 目录下开的会话，且 `AGENTS.md` 存在 |
| 提交报 `Author identity unknown` | 没设提交身份，见下面《提交身份》 |

## PATH 修复（Git 装了但 `git` 命令用不了）

真实案例：Git 装在 `D:\claudecode\Git`，但系统 PATH 里写的是 `D:\claude code\Git\cmd`（多了个空格），
所以 `git --version` 报"不是内部或外部命令"。

**诊断**：

```powershell
# 看 PATH 里登记的 git 路径是否真实存在
($env:Path -split ';') | Where-Object { $_ -match 'Git' } | ForEach-Object {
    "{0}  ->  {1}" -f $_, (Test-Path $_)
}
```

输出里出现 `False` 的那条就是坏路径。

**修法 A（无需管理员，推荐）**：把正确路径加到用户 PATH

```powershell
$correct = "D:\claudecode\Git\cmd"          # 换成你自己 git.exe 所在目录
$userPath = [Environment]::GetEnvironmentVariable('Path','User')
if ($userPath -notlike "*$correct*") {
    [Environment]::SetEnvironmentVariable('Path', "$userPath;$correct", 'User')
    "已追加，重开终端生效"
}
```

**修法 B（需管理员）**：`系统属性 → 环境变量 → 系统变量 Path`，把坏的那条改成正确的。

> 注意：本项目的两个脚本**不用改 PATH 也能跑**，它们会自动去常见安装目录找 `git.exe`。
> PATH 只影响你手动敲 `git` 命令。

## 提交身份（每个成员只需设一次）

```powershell
git config --global user.name "你的真名"
git config --global user.email "你的邮箱"
```

没设这个，`git commit` 会直接报 `Author identity unknown`。三人各设各的，提交记录里就能分清谁改了什么。
