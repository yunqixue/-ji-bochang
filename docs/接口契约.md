## 使用前必读：给 AI 的硬规则

> 这一节是写给**三个 AI 实例**看的。人的任务判断在别处，这里只讲不许碰的红线。

1. **字段名以 `src/shared/contracts.py` 为准**，必须完全一致，含大小写。本文档与它不一致时，**停下来问人**，不要自己挑一个。
2. **禁止自行新增字段、改字段名、改嵌套结构。** 需要加字段时按顺序做三件事：
   在这里加一行 → 改 `contracts.py` 并给默认值（保证老调用不崩）→ 在群里说明。
3. **情绪标签只能从第 4 节那张表里取**，禁止自创（自创等于要新增一张表情图，三天内没有这个预算）。
4. **数值范围不许越界**（越界前端会算出畸形的语速/音高）：
   - `emotion_score` / `intensity`：0.0 ~ 1.0
   - `valence`：−1.0 ~ 1.0 ｜ `arousal`：0.0 ~ 1.0
   - `speech_rate`：0.5 ~ 2.0 ｜ `pitch_shift`：半音，建议 −5 ~ +5
5. **失败必须用统一格式返回**，不许把裸异常抛给前端：
   ```json
   {"error": "原因", "reply_text": "给用户听的兜底话术", "avatar": {"expression": "empathic", "state": "idle"}}
   ```
6. **前端不得依赖 `raw` / `debug` 字段**——它们随时可能为空或改结构，只用于调试。
7. **时间戳一律 Unix 秒（float）**，不要用毫秒、不要用字符串日期。
8. **不许引入流式（SSE/WebSocket）**。三天内只做同步返回。

## 0. 总体数据流

```
浏览器 ──(录音 webm / 文字)──►  POST /api/chat
                                     │
                      ┌──────────────┴──────────────┐
                      ▼                             ▼
              感知模块(ASR+情绪)            记忆模块(取历史)
                      │                             │
                      └──────────► 认知模块(LLM) ◄──┘
                                     │
                          情绪标签 + 人设回复
                                     │
                      ┌──────────────┴──────────────┐
                      ▼                             ▼
              表现模块(TTS 生成 mp3)          返回 JSON
                                     │
                          前端：换形象表情 + 播放语音
```

**模块之间只传下面两个结构**：`PerceptionResult`（感知 → 认知）、`CognitionResponse`（认知 → 表现）。

## 1. HTTP 接口（B 和 C 之间唯一的对接面）

### `POST /api/chat`

请求：`multipart/form-data`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `session_id` | str | ✅ | 前端生成并保存（`localStorage` 里一个 uuid），用于多轮记忆 |
| `text` | str | ⬜ | 文字输入时传；与 `audio` 二选一 |
| `audio` | file | ⬜ | 录音文件，`audio/webm;codecs=opus`；与 `text` 二选一 |

响应：`application/json`

```json
{
  "session_id": "uuid",
  "turn": 3,
  "perception": {
    "timestamp": 1760000000.0,
    "text": "我今天面试又没过……",
    "emotion_label": "sad",
    "emotion_score": 0.82,
    "valence": -0.61,
    "arousal": 0.35,
    "modality": "audio",
    "raw": {}
  },
  "response": {
    "reply_text": "听起来挺难受的，愿意跟我说说是哪一轮卡住了吗？",
    "target_emotion": "empathic",
    "intensity": 0.7,
    "speech_rate": 0.85,
    "pitch_shift": -2.0,
    "gesture": null,
    "memory_used": ["turn:2"],
    "debug": {"strategy": "comfort_probe"}
  },
  "audio_url": "/static/tts/8f3a1c.mp3",
  "avatar": {
    "expression": "empathic",
    "state": "speaking"
  },
  "lipsync": {
    "words": ["听起来", "挺", "难受", "的"],
    "wtimes": [12, 380, 460, 720],
    "wdurations": [368, 80, 260, 180]
  },
  "latency_ms": 1830
}
```

### 形象字段 `avatar`（C 直接消费）

| 字段 | 类型 | 取值 | 说明 |
|---|---|---|---|
| `expression` | str | 见 §4 情绪标签表 | 前端按此换个图：`assets/images/expr_<expression>.webp` |
| `state` | str | `speaking` / `idle` | TTS 有音频时给 `speaking`，无音频时给 `idle` |

- `avatar` 字段**缺失或为 null 时**，前端沿用上一张表情，不报错
- 前端换图必须交叉淡入（`opacity` 200ms），不要直接换 `src`

### 唇形同步字段 `lipsync`（v0.4 新增，可选）

| 字段 | 类型 | 说明 |
|---|---|---|
| `words` | list[str] | 分词文本（edge-tts WordBoundary） |
| `wtimes` | list[int] | 每个词的开始时间，**毫秒**，与 words 等长 |
| `wdurations` | list[int] | 每个词的时长，毫秒 |

- 仅当本次语音由 edge-tts 在线合成时才有；SAPI/离线兜底/老缓存返回 `null`
- 前端 3D 形象用它做逐词口型同步；为 `null` 时前端退回音量驱动口型
- **老前端不读这个字段也能正常工作**（纯新增，无破坏性）

### 规则

- `audio_url` 为 `null` 时前端只显示文字（TTS 失败不算请求失败）
- 任何一端出错，返回 `{"error": "...", "reply_text": "<兜底话术>", "avatar": {"expression": "empathic", "state": "idle"}}`，前端照样显示兜底话术
- **不做流式**（三天内不碰 SSE，先把同步返回做稳）

### 其他接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 返回聊天页面 |
| GET | `/api/health` | 健康检查，返回 `{"ok": true, "asr": "...", "tts": "..."}` |
| POST | `/api/reset` | `{"session_id": "..."}` 清空该会话记忆 |

## 2. 感知 → 认知：`PerceptionResult`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `timestamp` | float | ✅ | Unix 秒 |
| `text` | str | ✅ | ASR 文本，或用户直接输入的文字 |
| `emotion_label` | str | ✅ | 取值见 §4 |
| `emotion_score` | float | ✅ | 0.0–1.0 置信度 |
| `valence` | float | ✅ | 效价 −1.0（负）~ 1.0（正） |
| `arousal` | float | ✅ | 唤醒度 0.0（平静）~ 1.0（激动） |
| `modality` | str | ✅ | `audio` / `text` |
| `raw` | dict | ⬜ | 调试信息，认知模块不得依赖 |

---

## 3. 认知 → 表现：`CognitionResponse`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `reply_text` | str | ✅ | 要说的文字 |
| `target_emotion` | str | ✅ | 智能体此刻的情绪，取值见 §4 → 直接驱动形象表情 |
| `intensity` | float | ✅ | 0.0–1.0 |
| `speech_rate` | float | ⬜ | 0.5–2.0 倍速，默认 1.0 → edge-tts 的 `rate` |
| `pitch_shift` | float | ⬜ | 半音偏移，默认 0 → edge-tts 的 `pitch` |
| `gesture` | str \| null | ⬜ | 三天内固定 `null` |
| `memory_used` | list[str] | ⬜ | 本次引用的记忆标识 |
| `debug` | dict | ⬜ | 策略名等 |

## 4. 情绪标签表（三层 + 形象必须同一套）

| label | 含义 | 中文 | 有对应形象图 |
|---|---|---|---|
| `neutral` | 中性 | 平静 | ✅ `expr_neutral.webp` |
| `happy` | 高兴 | 开心 | ✅ |
| `sad` | 悲伤 | 难过 | ✅ |
| `anxious` | 焦虑 | 紧张 / 担心 | ✅ |
| `angry` | 愤怒 | 生气 | ✅ |
| `surprised` | 惊讶 | 意外 | ✅ |
| `empathic` | 共情 | 关切（**主要出现在 `target_emotion`**） | ✅ |

> 新增标签意味着**要新增一张表情图**，三天内不要再加。

## 5. 记忆结构（三天内最简单的可行版）

```python
MEMORY[session_id] = {
    "turns": [ {"user": str, "assistant": str, "emotion": str}, ... ],  # 最近 8 轮
    "summary": str,     # 超过 8 轮时，把更早的压成一段话
    "count": int,       # 总轮数，即响应里的 turn
}
```

- 存进程内存，服务重启即清空 —— **三天内可以接受**
- 记忆读写只由 B 的认知模块负责，C 只管传 `session_id`

---

## 6. 约定

- **单位统一**：时间戳 Unix 秒；录音 16kHz 单声道或浏览器默认
- **失败要显式**：模块出错返回 `None` + 原因，不要返回假默认值让下游猜
- **mock 先行**：今天下午之前每人交一个返回固定样例的 mock，端到端就能提前联调
- **不做流式、不做鉴权、不做并发优化、不做口型同步**（三天内明确排除）
