# 疑难排查（一般不用看，卡住了再来）

> 这份是给"照着 使用方法.txt 做但卡住了"的情况。
> 命令都在 **PowerShell 黑窗口**里执行：按 `Win` 键 → 输入 `powershell` → 回车。

---

## 1. 提示 `git 不是内部或外部命令`

**原因 1（最常见）：装完 Git 没重开窗口。** 把黑窗口全关掉，重新打开一个。

**原因 2：PATH 指错了。** 真实案例：Git 装在 `D:\claudecode\Git`，
但系统 PATH 里写的是 `D:\claude code\Git\cmd`（**多了一个空格**），所以永远找不到。

诊断（看哪条路径是假的）：

```powershell
($env:Path -split ';') | Where-Object { $_ -match 'Git' } | ForEach-Object {
    "{0}  ->  {1}" -f $_, (Test-Path $_)
}
```

输出里 `False` 那条就是坏路径。

修法（不需要管理员，推荐）：把真实路径追加到用户 PATH

```powershell
$correct = "D:\claudecode\Git\cmd"    # 换成你自己 git.exe 所在目录
$userPath = [Environment]::GetEnvironmentVariable('Path','User')
if ($userPath -notlike "*$correct*") {
    [Environment]::SetEnvironmentVariable('Path', "$userPath;$correct", 'User')
    "已追加，重开窗口生效"
}
```

修法 B（需管理员）：`系统属性 → 环境变量 → 系统变量 Path`，把坏的那条改成正确的。

> 注意：**项目的 push.cmd / pull.cmd 不用管 PATH 也能跑**，它们会自动去常见目录找 `git.exe`。
> PATH 只影响你手动敲 `git` 命令。

## 3. 提示 `Author identity unknown`

没设提交身份。执行一次（换成你自己的）：

```powershell
git config --global user.name "你的真名"
git config --global user.email "你的邮箱"
```

三人各设各的，提交记录里就能分清谁改了什么。

## 4. 提示 `Authentication failed` / `403`

密码填错。Gitee 的 HTTPS 推送**不能用登录密码**，要用**私人令牌**：

Gitee → 头像 → 设置 → 安全设置 → 私人令牌 → 生成新令牌 → 权限勾 `projects` → 生成 → 复制。

⚠️ 令牌只显示一次，先存记事本。

## 8. 提示冲突 / `conflict` / `CONFLICT`

**停手，不要自己乱改乱删。** 详细处理步骤见第 12 节。

一句话原则：**先 `git rebase --abort` 退出冲突，再决定怎么合**，一步都不会丢。

## 11. 文件被删了 / 被改坏了，怎么恢复

**先别慌，只要之前 push 过，东西一定还在 git 历史里。**

### 情况 A：发现某个文件不见了

```powershell
# 1. 看是谁、哪次提交删的
git log --oneline --diff-filter=D -- "路径/文件名"

# 2. 从最近一次有它的提交里恢复（用上面查到的提交号的前一个）
git checkout <提交号>~1 -- "路径/文件名"
```

### 情况 B：文件被改坏了，想回到某个版本

```powershell
# 看这个文件的历史
git log --oneline -- "路径/文件名"

# 恢复到指定版本（只恢复这一个文件，不动别人）
git checkout <提交号> -- "路径/文件名"
```

### 情况 C：想看队友这次到底改了什么

```powershell
# 这次 pull 带下来的所有改动（一行一个文件）
git log --stat -3 origin/main
```

> 现在 `pull.cmd` 拉完之后会**自动列出本次被改动/删除的文件**，
> 看到 `D`（deleted）开头的行就要警觉，立刻问是谁删的。

### 情况 D：自己本地改乱了，但还没提交

```powershell
git checkout -- .          # 丢弃全部未提交改动（小心，不可恢复）
git checkout -- "某个文件"   # 只丢一个文件
```

### 防护习惯（比恢复更省事）

1. **每天收工 push** —— 只要推上去过，删了都能找回；没推的东西丢了就是真丢了
2. **pull 之后扫一眼文件清单**，看到意外删除立刻问
3. **不跨模块改** —— 各自目录各自管，AI 也一样
4. 重要节点（比如跑通端到端）打个标签：`git tag v0.1-endtoend`

## 12. pull 撞车了怎么处理（真实案例：2026-10-23）

> **本文已于 2026-10-23 修订**：项目里所有 pull 都改成 **merge 方式**（`--no-rebase`），
> 因为 rebase 撞车后要继续 `git rebase --continue`、还可能弹编辑器，三个人都卡死过。
> 如果你之前用旧版本撞过车，仓库里可能残留 rebase 状态，**先执行 `git rebase --abort` 清掉**。

### 先看懂报错

```
error: Pulling is not possible because you have unmerged files.
[CONFLICT] pull stopped: these files were changed by both sides -
          docs/xxx.md
```

意思：**你和队友改了同一个文件的同一片区域**，git 不知道该留谁的。
如果提示里出现 `rebase-merge directory`，说明还有一次没做完的 rebase 卡在那里，**连 pull 都启动不了**。

### 第一步：先清理残留状态（什么都不丢）

在项目文件夹里打开 PowerShell：

```powershell
git rebase --abort
git status
```

`git rebase --abort` 是**取消**残留的 rebase（不是"使用 rebase"）——
把你送回 pull 之前的样子，**你本地的东西物归原主**。

> 如果这句报 `no rebase in progress`，说明没有残留，忽略它，直接看 `git status`。
> 此时若显示 `You have unmerged paths`，改用 `git merge --abort`。

### 第二步：看自己有没有独立的提交

```powershell
git log --oneline origin/main..HEAD
```

| 结果 | 说明 | 走哪条 |
|---|---|---|
| **没有输出** | 你只是改了工作区文件，没提交过 | → 路线 A |
| **有输出** | 你有自己的提交 | → 路线 B |

### 路线 A：没有自己的提交（最常见，最省事）

```powershell
# 1. 先备份要保的内容（复制文件到桌面，或用记事本存一份）
# 2. 丢弃本地改动
git checkout -- .
# 3. 重新拉取（用 merge，不要用 --rebase）
git pull --no-rebase origin main
```

拉下来之后，如果你想加的内容被队友的版本覆盖了，**重新在他最新版本上改一遍**——
因为文档一般是你补几句，重加比合并快。

### 路线 B：有自己的提交（不能丢）

```powershell
git stash push -u -m "我的改动"
git pull --no-rebase origin main
git stash pop
```

`stash pop` 很可能再冲突一次。这时**不用怕**，打开报冲突的文件，会看到：

```
<<<<<<< HEAD
（队友的版本）
=======
（你的版本）
>>>>>>> stash
```

**中文文档的合并规则**：

1. 删掉 `<<<<<<<`、`=======`、`>>>>>>>` 这三行标记
2. **两边内容都保留**，按前后顺序排好（文档大多是"各加了一段"，两边都要）
3. 存盘，然后：

```powershell
git add docs
git commit -m "docs: 合并文档冲突（保留双方内容）"
```

### 实在搞不定

跑这句，把所有东西原样打包，群发给队长：

```powershell
git status
git log --oneline -5
```

或者最省事：**把窗口截图发群里**，别自己硬撑着改。

### 怎么避免下次再撞

1. **改文档前先 `pull`**（这是九成冲突的根源：先改后拉，必撞）
2. 只在自己负责的文档上动手（见 `AGENTS.md` 第 10 节的归属表）
3. 追加型文件（决策记录 / 交接记录）**只加末尾，不动别人的行**
4. 想改别人的文档 → 在群里说，让维护人改

## 13. 语音识别（ASR）装不上 / 装上了但报错

### 症状对照表

| 报错 | 原因 | 处理 |
|---|---|---|
| `[WinError 5] 拒绝访问: 'C:\Users\xxx\.cache\huggingface'` | faster-whisper 默认把模型缓存写到用户目录，受限账户写不进去 | 用 `python experiments/download_asr_model.py` 下载到项目 `data/models/`，代码会自动优先用本地模型 |
| 下载卡住不动 / 几十分钟没进展 | huggingface_hub 在国内常卡死 | 同上，用项目自带下载器（走 hf-mirror + 长度校验 + 重试） |
| `token was not found in the prompt` / `The current model is English-only` | 模型文件被截断，或下成了英文版 | 跑 `python experiments/download_asr_model.py --check`，它会检查词表行数（多语言版必须是 51865 行），不达标就删掉 vocabulary.txt 重下 |
| `pip install faster-whisper` 卡在依赖解析 | pip 在回溯 ctranslate2 / onnxruntime 版本 | 加 `--only-binary :all:`（只用现成轮子，不现场编译） |
| 识别出来是英文 / 乱码 | 模型是英文版，或没设中文 | 确认模型目录里 vocabulary.txt 是 51865 行；代码里已默认 `language="zh"` |

### 模型放哪里

```
data\models\faster-whisper-base\     ← base 模型（约 150MB，够演示）
    config.json
    model.bin
    tokenizer.json
    vocabulary.txt      ← 必须是 51865 行（多语言版）
```

**模型不进 git 仓库**（`data/models/` 已 gitignore）。队友之间共享就直接拷这个文件夹。

### 一句话验证

```powershell
python experiments/check_env.py              # 看 "ASR 模型就绪" 是否 ✅
python experiments/download_asr_model.py --check
```
