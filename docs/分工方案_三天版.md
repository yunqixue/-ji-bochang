## 三、必须人做 vs 交给 AI

### 不可外包（AI 一律不替你决定）

| 工作 | 归属 | 原因 |
|---|---|---|
| 产品定位与场景取舍 | A | 决定产品生死，没有标准答案 |
| 人设卡与行为底线 | A | 涉及价值观，且要长期一致 |
| 用户访谈与真人测试 | A | 需要观察真人的表情、语气、沉默 |
| 安全红线与伦理判断 | A | 法律与伦理责任必须有人承担 |
| 最终体验验收（"够不够暖"） | A | 主观体验，AI 替代不了目标用户 |
| 架构取舍 | B / C | 影响三天能不能收口 |
| 现场演示的临场判断 | 三人 | 演示翻车只有人能救 |

### 高比例交给 AI（约 90% 由 AI 产出，人只评审）

功能编码 · 接口文档初稿 · 提示词候选与对照 · 测试用例生成 · 部署脚本 · 技术文档与汇报材料起草。

**标准姿势**：人给判断目标 → AI 出初稿与批量候选 → 人筛选定稿 → AI 执行落地 → 人验收。

**反面案例**：只说一句"做个情感智能体"，等 AI 交成品。这样产出的一定是技术正确、情感空洞的机器人。

| # | 交接内容 | 交付方 → 接收方 | 验收标准 |
|---|---|---|---|

## 五、三天里的降级顺序（时间不够时按此砍）

**文字对话 > 语音输出 > 形象 > 语音输入 > 多轮记忆**

砍的时候**永远先砍后面的**。形象和语音输出必须保住——因为演示时评委看到的就是"一个有表情、会说话的角色"，记忆深度是最不容易被察觉的。

| 卡住的情况 | 降级方案 |
|---|---|
| ASR 装不上 / 模型下不下来 | 保留文字输入框，演示时打字 |
| TTS 连不上 | 切 pyttsx3 离线发音，或只显示文字 |
| 形象图来不及 | 3 张（neutral/sad/happy）够演示，其余复用 neutral |
| 记忆没做完 | 只做最近 3 轮，不做摘要 |
| 现场网络差 | 录屏兜底 + 预置 3 条兜底话术 |
